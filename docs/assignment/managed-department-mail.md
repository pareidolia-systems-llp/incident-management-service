# Managed department mail rollout

Keep production incident access disabled while its activation guard rejects startup. The five-department requirement applies to guarded intake. Legacy intake continues unchanged while the guard is off.

Before migration, verify canonical names, active states and column types in the existing department catalog. An existing Human Resources row is the HR option and retains its ID. Stop if both HR and Human Resources exist, or if any of the five required departments is inactive. Take a backup and test restoration on disposable MySQL. Apply the existing responsible department and department-head email receipt migrations first. Apply the managed recipient migration once, with the delivery flags off. Its initial seed is a deployment record. Subsequent changes are versioned and record the verified administrator, prior and new values, time and reason. Grant the application SELECT/INSERT/UPDATE on the recipient table and SELECT/INSERT on the audit table. Review the migration account separately.

Enable the management API with INCIDENT_EMAIL_RECIPIENT_ADMIN_ENABLED and the frontend panel with VITE_DEPARTMENT_MAIL_RECIPIENTS_ENABLED, using the existing approved Employee Management access and active employee-mapping administrator capability. Managed delivery is enabled separately by INCIDENT_EMAIL_MANAGED_RECIPIENTS_ENABLED and also requires verified routing, case access, and the approved mail origin, transport and environment. Do not enable SMTP in B4. Rehearse the DDL on the isolated disposable schema using fixture mailboxes in place of the initial office seed. B4 accepts the complete two-table migration and enables recipient administration for authorized fixtures with mail delivery off. The old matrix remains the source only when managed mode is off.

Managed email uses the selected department after first classification. Recipients must match active, signed-in app users with current department membership. Restricted cases also require the separately approved restricted matrix, explicit VIEW and the HR policy. A case classified as HR outside the HR department is withheld under managed routing. A configured address cannot grant access. Head delivery keeps its existing approvals and shares the receipt by incident and account with managed department email. An uncertain or unfinalized claim needs reconciliation before any manual action.

Global IT and HR oversight remains in-app and uses independently verified account IDs. Confirm the designated app-user identities and permissions before enabling flags. No department recipient entry creates an oversight role, assignment or case grant.

To suspend delivery, disable verified mail and the applicable mail feature flags together so legacy mail is not selected unintentionally. To roll back the admin UI/API, disable both management flags and retain recipient and audit data and receipts. Restore from the approved backup only if recovery is necessary. Preserve incident department references and receipt state when restoring.
